# Stage 4：真实生成与安全修复

日期：2026-10-06

## 结论

DeepSeek 文本生成链路已通过真实端到端验证。IfPlay 能从网页提交想法，经 OpenGame 生成多文件网页游戏，并在受限 iframe 中完成一轮核心玩法。

当前结论仅适用于受控本地测试。OpenGame 上游依赖仍有高危与严重漏洞，且尚未接入生产级云端沙箱，不能据此宣布可公网部署。

## 本阶段发现并修复的问题

### 1. OpenGame 工作目录缺少模板位置

IfPlay 在 OpenGame 仓库外启动生成时，上游默认相对路径不可靠。调用层现显式传入 `GAME_TEMPLATES_DIR` 与 `GAME_DOCS_DIR`。

### 2. `--yolo` 权限过大

真实界面测试中，OpenGame 在 `--yolo` 模式下启动 Shell 并进行全盘目录搜索。该任务被人工终止，未作为成功证据。IfPlay 已改用 `--approval-mode auto-edit`，不再授予生成任务 Shell 权限，并显式关闭遥测。

### 3. 多文件游戏在试玩区不可交互

原试玩区仅把 `index.html` 写入 iframe 的 `srcdoc`，导致相对引用的 CSS 和 JS 无法加载。后端现仅从当前版本目录读取本地样式与脚本并内嵌到预览 HTML，同时校验路径不得越出版本目录。

## 风险与缺口

- 当前仍是宿主机本地 `auto-edit`，不是 PRD 要求的独立云端沙箱。
- 当前预览内嵌覆盖本地 CSS 与 JS；图片、字体等二进制资源的安全打包尚未完成。
- 尚未取得本次 DeepSeek 调用的可信人民币成本数据。
- 万相图片链路尚未配置和测试。
