# Stage 1 技术适配结论

日期：2026-10-06  
状态：通过，可以进入后端实现

## 核查对象

- OpenGame 仓库：`https://github.com/leigest519/OpenGame`
- 核查版本：0.6.0
- 运行环境要求：Node.js 20 及以上
- 当前本机 Node.js：24.20.0，满足要求

## 已验证事实

1. OpenGame 是端到端网页游戏生成框架，但当前主要入口是命令行和实验性 TypeScript SDK，不是现成的 HTTP 后端。
2. 主 Agent 使用 OpenAI 兼容接口，可通过 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL` 配置，具备接入 DeepSeek 的技术条件。
3. 图片模块已经提供 `tongyi` 供应商配置，可通过阿里云 DashScope 接入万相。
4. 视频供应商可以不配置，符合 IfPlay 测试版不做视频的范围。
5. OpenGame 支持无界面单次生成，并能在指定项目目录中写入和构建游戏。
6. 上游许可证为 Apache License 2.0，引入代码时必须保留许可证和版权信息。

## 采用方案

不重写 OpenGame 的 Agent 生成循环。IfPlay 在其外层增加一个轻量服务层：

`IfPlay 前端 → IfPlay HTTP API → 双并发任务队列 → OpenGame 适配器 → 独立项目工作区 → 静态试玩产物`

服务层负责创建匿名项目和任务、保存真实任务状态与版本、限制最多两个同时运行的生成任务、调用 OpenGame 完成生成或修改，并在失败时保留上一可玩版本。

## 两天版本的实现边界

- 后端先使用本地持久化与受控工作区跑通流程，接口设计保留替换为数据库和云沙箱的边界。
- 没有真实模型密钥时允许开启明确标识的开发模式，用固定的本地样例验证队列、状态和版本流程。
- 开发模式不能计入真实生成成功率，也不能在页面上标记为真实 AI 生成。
- 本轮不使用 OpenGame 的 `--yolo` 权限模式作为生产方案；正式外部测试前必须迁移到独立沙箱并限制工具和网络。

## 主要风险与处理

| 风险 | 当前处理 |
| --- | --- |
| OpenGame 不是服务器 | 增加 IfPlay API 和任务队列封装 |
| 生成任务可能执行模型产生的命令 | 两天版只用于受控测试；公开测试前必须进入隔离沙箱 |
| SDK 仍为实验性 | 先通过稳定的命令行边界调用，保留后续切换 SDK 的适配层 |
| 月预算只有 200 元 | 并发限制为 2，限制图片和修复次数，开发默认不调用付费模型 |
| 企业认证尚未确定 | 不承诺正式云端上线，仅交付本地或测试环境演示 |
