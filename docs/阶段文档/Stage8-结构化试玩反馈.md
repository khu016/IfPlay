# Stage 8：结构化试玩反馈

更新时间：2026-10-07  
状态：完成

## 目标

把用户试玩后的“感觉不对”翻译成边界明确、可以确认的修改计划。系统必须先说明会改变什么、保持什么、是否触碰玩法合同，再允许创建新版本任务。

## 已完成

1. 增加七个常见反馈入口，并保留自然语言补充。
2. 使用 DeepSeek 把反馈整理成严格结构化的修改计划。
3. 修改计划包含分类、摘要、改变项、保持项、合同影响和预计消耗。
4. 预览计划时不创建生成任务，也不会改动当前可玩版本。
5. 用户确认后，后端使用已保存计划创建任务，不接受客户端临时替换执行指令。
6. 修改触碰核心循环、成功条件、失败条件或整体视觉方向时，界面要求重新确认合同变更。
7. 合同变更确认追加到合同修订记录；普通修改明确保护未点名内容。
8. 修改失败时保留原可玩版本，并保存可理解错误。
9. 修改计划和确认状态可在页面刷新后恢复。

## 真实验收

- 对象：现有 DODGE 30 可玩版本。
- 反馈：节奏太慢。
- DeepSeek 输出：4 项具体节奏调整和 4 项保持不变内容。
- 合同判断：不改变核心循环、结束条件和整体视觉方向。
- 任务状态：只完成修改计划预览，没有确认或启动 OpenGame 生成，避免额外生成费用。
- 桌面和 390×844 手机布局通过，浏览器控制台无错误或警告。
- 自动测试 11/11 通过。
