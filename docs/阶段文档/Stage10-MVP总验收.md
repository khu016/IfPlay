日期：2026-10-07

## 验收范围

每个案例都实际经过以下链路：中文想法 → DeepSeek 玩法策划 → 选择低风险提案 → 万相三分区参考风格板 → 玩法合同确认 → OpenGame 首版生成 → 预览自动检查 → 桌面浏览器核心交互 → 390×844 移动视口冒烟。

真实生成并发始终不超过 2。每个项目只生成一张参考风格板，没有自动重试或重复付费生成。

## 自动检查

五个产物均满足：

- IfPlay 预览接口返回成功，HTML 内容完整。
- 包含移动端 viewport 和实际交互代码。
- 有开始或重新开始入口。
- 不引用远程脚本、样式或图片资源。
- 单版本总产物远低于 15MB 限制。

可复跑脚本为 `npm run acceptance:stage10`。本地详细报告和匿名项目凭证保存在 `.data/stage10-acceptance/`，该目录已被 Git 忽略，不会提交到仓库。

## 事实边界

- 5/5 表示本地受控测试环境中的 MVP 主链路和代表性玩法交互通过，不代表生产级稳定性、内容安全或公网承载能力已经完成。
- 桌面端验证了每类游戏的代表性核心状态变化；移动端完成真实 390×844 视口下的启动和交互入口冒烟，不等同于覆盖所有手机、浏览器与完整通关。
- 五次万相调用各返回一张三分区风格板。OpenGame 生成的五个游戏没有新增位图文件，主要使用 CSS、Canvas 和内联图形。
- 精确人民币成本无法由当前返回值计算，仍需等待供应商账单核对；因此不声称已经证明低于月预算 200 元，只能确认本轮没有重复调用。

## 暂不属于本阶段完成范围

- 正式云端沙箱与生产级隔离。
- 内容审核、滥用防护和公开分享。
- 邀请码、10–20 人真实用户测试和运营后台。
- 多设备兼容矩阵、长时间稳定性和性能压测。
- 供应商账单对账与人民币成本看板。
